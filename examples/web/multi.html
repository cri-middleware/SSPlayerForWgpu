device は 1 つ、canvas は要素ごと

このページのアニメーションはすべて <ss-player-webgpu> です。要素はそれぞれ自分の <canvas> を持ちますが、WebGPU の device・パイプライン・アトラスはページで 1 組。右上の HUD の GPUDevice は、全要素の el.ctx が同一オブジェクトか数えた実測値です。

<ss-player-webgpu src="Ringo.ssab" autoplay></ss-player-webgpu>

ページ側で書くのはこれだけです。defineSsPlayerWebGPUElement() を 1 回呼べば、何個置いても最初の 1 個が作った device を全員で共有します。

文中にも置けます

要素は行の中にも収まります — display: inline-block にして高さを与えるだけで、行送りの一部として扱われます。canvas は要素の CSS ボックスに追従するので、ウィンドウ幅を変えれば解像度も付いてきます。

その代わりに払っているもの

canvas が要素の数だけあるということは、合成する面もその数だけあるということです。1 枚の canvas に何体も描く形（デモ index の ②）なら描画は 1 パスで済み、キャラクター同士の前後関係も 1 つの order で決まります。ページの流れに沿って散らしたい・CSS で飾りたいときは要素、1 つの舞台に大勢を並べたいときは 1 canvas に N 体 — というのが使い分けです。

画面外に出たら止まります

要素は IntersectionObserver と visibilitychange を見ていて、画面外・バックグラウンドタブでは rAF を止めます（pause-when-hidden、既定 on）。各アニメーションの下にフレーム番号を出しているので、スクロールで画面外に送ると数字が止まり、戻すと止まったところから続くのが読めます。HUD の「いま進んでいる」も同時に減ります。

下の 1 体だけ pause-when-hidden="false" です。画面外に送っても数字が進み続けるので、止まっているのが既定の挙動だと確かめられます。

数を増やしても device は増えません

以下は数を稼ぐためだけのものです。HUD の canvas は増え、GPUDevice は 1 のままです。

同じパックを何度置いても、アトラスのアップロードは 1 回です。テクスチャは device に紐づく SSRenderer が持っていて、2 体目の load は「もうある」と分かった時点でデコードもアップロードもしません。
