# パフォーマンス

画面に何体まで出せるのか。答えはコンテンツ次第なので、Player はそれを測るための数字を報告します。

## キャラクター 1 体のコスト

何を描いていても成り立つことが 3 つあります：

* **CPU コストは頂点ではなくパーツ単位です。** 頂点バッファはありません。CPU はパーツ 1 つにつきプリミティブを 1 つ書き、頂点ステージがそれを展開します。200 パーツのキャラクターは
  200 回の小さな書き込みです。
* **アトラスはデバイスごとに 1 回だけアップロードされます。** テクスチャマップはデバイススコープなので、同じパックを 5 体で表示してもアップロードは 1 回です。
* **1 ターゲットのキャスト全体で 1 レンダーパスです。** 全キャラクターが 1 回の `update` と 1 つのパスを通るので、2 体目のコストは再生ツリーだけで、GPU 側には増えません。

## 何も動いていないシーン { #a-scene-with-nothing-moving }

シーンのどのキャラクターにも動くものがないとき、`update` は前回作ったフレームをそのまま残します。評価も作り直しも転送もせず、`draw` は同じフレームをもう一度描きます。動くものがないとは、キャラクターが停止中か再生を終えているか、または一時停止中で独立再生のエフェクトやインスタンスを含まず、しかもトラックのフェードや他のトラックが姿勢を動かしていない状態です（[モーションブレンド](./motion-blending.md)を参照）。

1 体でも動いていれば、フレーム全体を作り直します。シーンのキャラクターは 1 つのバッファを共有しているためです。キャラクターの描くものを変える呼び出し（トラックやパーツのオーバーライド、シーク、配置の変更など）は 1 回だけ作り直します。同じ配置・アルファ・tint・表示状態を書き直してもコストはかからないので、ホストは毎フレーム書いて構いません。フレームを残した `update` では `uploaded_bytes` が `0` になります。

## カウンタを読む

=== "Rust"

    ```rust
    let s = scene.stats();
    println!("{} players, {} prims, {} draws, {} bytes", s.players, s.prims, s.draw_calls, s.uploaded_bytes);
    ```

=== "C"

    ```c
    ss_scene_stats_t s;
    ss_scene_stats(scene, &s);
    ```

=== "JavaScript"

    ```js
    const s = surface.stats();   // { players, prims, drawCalls, uploadedBytes, ... }
    ```

| カウンタ | 意味 | Rust | C | JS |
|---|---|:--:|:--:|:--:|
| `players` | このフレームにジオメトリを出したキャラクター数 | ✅ | ✅ | ✅ |
| `prims` | フレーム内のパーツ・シェイプ・エフェクト粒子 | ✅ | ✅ | ✅ |
| `draw_calls` | 記録されたドロー数 | ✅ | ✅ | ✅ |
| `uploaded_bytes` | フレームのストレージバッファへの書き込み量 | ✅ | ✅ | ✅ |
| `mergeable_draws` | ドローリストのうちマージできる量 | ✅ | — | ✅ |
| `redundant_texture_binds` | 既にバインド済みのテクスチャを貼り直したドロー数 | ✅ | — | ✅ |
| `coverage_layers` | このフレームのマスクカバレッジパス数 | ✅ | — | — |
| `group_layers` | このフレームに 1 枚のレイヤーとしてフェードしたキャラクター数 | ✅ | ✅ | ✅ |
| `gpu_pass_time_ns` | 直近の計測パスの GPU 時間 | ✅ | ✅ | ✅ |

自分のコンテンツで見る最短経路は、`cargo run -p ssplayer-wgpu-viewer` に `.ssab` をドロップすることです。ネイティブビューアはどちらもこれを毎秒表示します。

`gpu_pass_time_ns` にはタイムスタンプクエリ付きで作られたデバイス（ブラウザでは `timestamp-query` が許可されていること）が必要です。無い場合は `None` / `0` / `undefined` になり、他のカウンタはそのまま使えます。値は 1〜2 フレーム遅れて届きます。それより早く読むにはパイプラインを止める必要があるためです。

## コストが大きいもの

| | |
|---|---|
| **カバレッジマスクバックエンド** | **マスクを使うキャラクター 1 体につき 1 パス／フレーム**。マスクライタが 24 を超えると、24 ごとにもう 1 パス。キャラクター単位では最大のコストで、[ステンシルがある環境で使わない](./masks.md)のはこのためです |
| **アトラスの種類が多い** | それぞれがバインドグループの切り替えです。`redundant_texture_binds` を見れば、描画順が不利に働いているか分かります |
| **group alpha** | オンのとき、**フェード中のキャラクター 1 体につき 1 パスとターゲット全面への合成 1 回／フレーム**。同時にフェードしている 1 体ごとに、ターゲットと同じ大きさのレイヤーが 1 枚要ります。数は `group_layers` で分かります。アルファ 1 のキャラクターにコストはかかりません。[キャラクター全体の tint とアルファ](./part-overrides.md#whole-character-tint-and-alpha)を参照 |
| **キャラクターが非常に多い** | キャラクター単位の CPU 走査はシングルスレッドです。同じキャラクターを同じタイミングで並べるなら、[群衆描画](./crowds.md)を使えば走査は 1 体分で済みます |
| **画面外のキャラクター** | `set_culled(true)` は描画だけでなくタイムラインの前進もスキップするので、コストはゼロになります。画面外のキャストにはこれを使ってください。`set_visible(false)` は代わりになりません。描画を飛ばすだけで、タイムラインは進み続けます |

## 数字がおかしいと思ったら

`mergeable_draws` と `redundant_texture_binds` は、レンダラーが置いている前提を自分のシーンで確かめられるように報告されています。ドローコールのマージ、バインドグループの重複排除、レンダーバンドル、バインドレステクスチャは 256 体のフレームに対して計測したうえで実装していません。理由は
[ROADMAP](https://github.com/cri-middleware/SSPlayerForWgpu/blob/main/ROADMAP.md) の
*Deliberate non-goals* にあります。自分のコンテンツでこの 2 つが大きい場合は、issue に値します。
