# パフォーマンス

画面に何体まで出せるのか。答えはコンテンツ次第なので、Player はそれを測るための数字を報告します。

## キャラクター 1 体のコスト

何を描いていても成り立つことが 3 つあります：

* **CPU コストは頂点ではなくパーツ単位です。** 頂点バッファはありません。CPU はパーツ 1 つにつき
  80 バイトのプリミティブを 1 つ書き、頂点ステージがそれを展開します。200 パーツのキャラクターは
  200 回の小さな書き込みです。
* **アトラスはデバイスごとに 1 回だけアップロードされます。** テクスチャマップはデバイススコープなので、
  同じパックを 5 体で表示してもアップロードは 1 回です。
* **1 ターゲットのキャスト全体で 1 レンダーパスです。** 全キャラクターが 1 回の `update` と 1 つのパスを
  通るので、2 体目のコストは再生ツリーだけで、GPU 側には増えません。

## カウンタを読む

=== "Rust"

    ```rust
    let s = scene.stats();
    println!("{} players, {} prims, {} draws, {} bytes", s.players, s.prims, s.draw_calls, s.uploaded_bytes);
    ```

=== "C"

    ```c
    ss_scene_stats_t s;
    ss_scene_stats(scene, &s);
    ```

=== "JavaScript"

    ```js
    const s = surface.stats();   // { players, prims, drawCalls, uploadedBytes, ... }
    ```

| カウンタ | 意味 | Rust | C | JS |
|---|---|:--:|:--:|:--:|
| `players` | このフレームにジオメトリを出したキャラクター数 | ✅ | ✅ | ✅ |
| `prims` | フレーム内のパーツ・シェイプ・エフェクト粒子 | ✅ | ✅ | ✅ |
| `draw_calls` | 記録されたドロー数 | ✅ | ✅ | ✅ |
| `uploaded_bytes` | フレームのストレージバッファへの書き込み量 | ✅ | ✅ | ✅ |
| `mergeable_draws` | ドローリストのうちマージできる量 | ✅ | — | ✅ |
| `redundant_texture_binds` | 既にバインド済みのテクスチャを貼り直したドロー数 | ✅ | — | ✅ |
| `coverage_layers` | このフレームのマスクカバレッジパス数 | ✅ | — | — |
| `gpu_pass_time_ns` | 直近の計測パスの GPU 時間 | ✅ | ✅ | ✅ |

自分のコンテンツで見る最短経路は、`cargo run -p ssplayer-wgpu-viewer` に `.ssab` をドロップすることです。
ネイティブビューアはどちらもこれを毎秒表示します。

`gpu_pass_time_ns` にはタイムスタンプクエリ付きで作られたデバイス（ブラウザでは `timestamp-query` が
許可されていること）が必要です。無い場合は `None` / `0` / `undefined` になり、他のカウンタはそのまま
使えます。値は 1〜2 フレーム遅れて届きます。それより早く読むにはパイプラインを止める必要があるためです。

## コストが大きいもの

| | |
|---|---|
| **カバレッジマスクバックエンド** | **マスクを使うキャラクター 1 体につき 1 パス／フレーム**。キャラクター単位では最大のコストで、[ステンシルがある環境で使わない](./masks.md)のはこのためです |
| **アトラスの種類が多い** | それぞれがバインドグループの切り替えです。`redundant_texture_binds` を見れば、描画順が不利に働いているか分かります |
| **キャラクターが非常に多い** | キャラクター単位の CPU 走査はシングルスレッドです |
| **画面外のキャラクター** | `set_visible(false)` は描画だけでなくタイムラインの前進もスキップするので、コストはゼロになります。画面外のキャストにはこれを使ってください |

## 数字がおかしいと思ったら

`mergeable_draws` と `redundant_texture_binds` は、レンダラーが置いている前提を自分のシーンで確かめられる
ように報告されています。ドローコールのマージ、バインドグループの重複排除、レンダーバンドル、バインドレス
テクスチャは 256 体のフレームに対して計測したうえで実装していません。理由は
[ROADMAP](https://github.com/cri-middleware/SSPlayerForWgpu/blob/main/ROADMAP.md) の
*Deliberate non-goals* にあります。自分のコンテンツでこの 2 つが大きい場合は、issue に値します。
