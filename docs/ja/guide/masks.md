# マスク

マスクパーツは、それが覆う範囲を切り抜きます（鍵穴越しのキャラクター、増減する HP バー、図形でくり抜かれたスプライト）。オーサリングするのはアーティストですが、Player は GPU が提供する何かで切り抜く必要があり、**その「何か」は描画ターゲット次第であって、アニメーション次第ではありません**。

同じ `.ssab` はどちらのバックエンドでも同じ見た目になります。変わるのは、あなたが用意するものです。

## 2 つのバックエンド

| バックエンド | 必要なもの | コスト | 使える Face |
|---|---|---|---|
| **ステンシル** | 描画する全パスに深度/ステンシルアタッチメント | 追加コストなし | Rust / C / JavaScript |
| **カバレッジビットマップ** | update と draw の間の 1 呼び出し | **マスクを使うキャラクター 1 体につき 1 パス／フレーム**。マスクライタが 24 を超えると、24 ごとにもう 1 パス | Rust / Bevy |

カバレッジは、貸せるステンシルを持たないレンダーパスのために存在します。Bevy の 2D 深度テクスチャは
`Depth32Float` でステンシルを持ちませんし、自前でパスを構成するエンジンは深度自体を公開していないこともあります。ステンシルが*使える*ならそちらが安いので、カバレッジは既定ではありません。

## Face ごとの扱い

=== "Rust"

    `SceneConfig` で選びます：

    ```rust
    // ステンシル — 全パスに対応する深度/ステンシルバッファを自分で付けます。
    SSScene::new(&device, &SceneConfig {
        color_format,
        stencil_format: Some(wgpu::TextureFormat::Depth24PlusStencil8),
        mask: MaskBackend::Stencil,
    });

    // カバレッジ — あなたのアタッチメントには何も要求しません。
    SSScene::new(&device, &SceneConfig {
        color_format,
        stencil_format: None,
        mask: MaskBackend::Coverage,
    });

    // マスク無し：マスクパーツは何も描かず、被マスク対象は切り抜かれずに描かれます。
    SSScene::new(&device, &SceneConfig { color_format, stencil_format: None, mask: MaskBackend::None });
    ```

    `stencil_format` の無い `MaskBackend::Stencil` は成立しないため、被マスクパーツを黙って切り抜かずに描くのではなく拒否されます（シーンは `None` にフォールバックします）。

=== "C"

    シーン記述子のフラグ 1 つです。ステンシルバッファは自動で確保されます。

    ```c
    ss_scene_desc_t desc = { /* ... */ .enable_mask = true };
    ```

    `enable_mask = false` なら、ステンシルを付けなかった場合とまったく同じくマスク無しで動きます。カバレッジバックエンドはこの Face には公開されていません。あれは自分でレンダーパスを持つホストのためのもので、この Face はそのパスを自分で持っているからです。

=== "JavaScript"

    設定項目はありません。サーフェスごとに深度/ステンシルテクスチャを確保し、ステンシルバックエンドを使います。

=== "Bevy"

    設定項目はありません。そして**カバレッジ**バックエンドになります。Bevy の 2D 深度がステンシルを持たないためです。そのコストが `SceneStats::coverage_layers` です。

## カバレッジで唯一守るべき順序

カバレッジバックエンドを自分で駆動する場合（Rust ホストやエンジンアダプタ）、規則は 1 つだけです：

```rust
scene.update(&mut renderer, &device, &queue, dt, &mut players);
scene.encode_mask_coverage(&mut renderer, &device, &mut encoder);  // <- この encoder と
let mut rpass = encoder.begin_render_pass(&descriptor);            // <- こちらを同じに
scene.draw(&renderer, &mut rpass);
```

**焼き込みと、それをサンプルするパスは 1 つの `CommandEncoder` に載せます。** 1 つの encoder 内のパスは順に実行されるため、ビットマップとそれをサンプルする変換の両方が*このフレームのもの*になり、食い違いようがありません。

この順序がすべてです。焼き込みを別の encoder・別のシステム・別のフレームに分けると、キャラクターを切り抜くマスクが 1 フレーム前のものになります。速い動きでクリップが 1 フレーム遅れて追従する形で見えます。

`MaskBackend::Stencil` のときこの呼び出しは無害な no-op なので、実行時にバックエンドを切り替えるホストでもそのまま置いておけます。

## 1 パスにキャラクターを積む

各キャラクターは、次のキャラクターが描かれる前に**自分が適用したステンシルライタを巻き戻します**。これが無いと、1 つのレンダーパスに 2 体置いたとき、1 体目のマスクが 2 体目を切り抜いてしまいます。

これは何もしなくても効きます。ここで触れておくのは、問題が現れるタイミングのためです。`LoadOp::Clear(0)`
で 1 体 1 パスで描いている限りこのバグは見えないので、キャストを 1 パスにまとめた日に初めて表面化します。

## 制限

* 1 体のキャラクターが同時に使えるマスクライタは、インスタンスの木全体で数えて**最大 96**です。インスタンスの中のマスクは呼び出し側が後から描くパーツも切り抜き続けるので、木のライタはまとめて数えます。上限は両バックエンド共通なので、どちらでも同じ見た目になります。カバレッジビットマップはライタ 1 つにつき 1 ビット、1 レイヤーに 24 ライタです。
* マスクパーツは切り抜き形状であって色ではありません。描かれるのはクリップであり、ピクセルではありません。
