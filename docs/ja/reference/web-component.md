# `<ss-player-webgpu>`

カスタム要素は**利便性のラッパー**です。1 要素＝1 キャンバス＝1 キャラクターで、1 体だけ表示する用途
（広告クリエイティブ、ページ隅のマスコット、CMS テンプレート内のキャラクター）への最短経路です。

2 つ目の実装ではありません。内部ではページの共有コンテキストからサーフェスを取り、そこにプレイヤーを
1 つ足しているだけなので、**1 ページに 10 個置いても `GPUDevice` は 1 つ、パイプラインは 1 セット、
アトラスのアップロードは 1 回**です。

## 登録する

```js
import { defineSsPlayerWebGPUElement } from '@spritestudio/ssplayer-wgpu/element';

defineSsPlayerWebGPUElement();                    // <ss-player-webgpu>
defineSsPlayerWebGPUElement('my-ss-player');      // ... 独自の名前で
```

登録は **import の副作用ではなく opt-in** なので、[JavaScript API](./js.md) だけを使うバンドルに要素は
含まれません。呼び出しは冪等で、`tag` 引数は、既定名で別の SpriteStudio Player が登録済みのページのために
あります。

```html
<ss-player-webgpu src="/assets/Basic.ssab" autoplay style="width:360px;height:360px"></ss-player-webgpu>
```

## 属性

| 属性 | 意味 |
|---|---|
| `src` | `.ssab` の URL。reference / embedded どちらでも可 |
| `pack` | パック名の上書き。既定は `.ssab` 内の名前 |
| `anim` | 再生するアニメーション。既定はパックが宣言する最初のもの |
| `autoplay` | ロード後に再生開始。**boolean 属性**なので、無ければ再生しません |
| `pause-when-hidden` | 画面外・バックグラウンド時に rAF ループを止める。**既定でオン** — `pause-when-hidden="false"` で解除 |

!!! warning "属性は接続時に読まれるだけで、監視されません"
    `attributeChangedCallback` はありません。生きている要素に `element.setAttribute('src', …)` しても
    **何も起きません**。実行時にパックを差し替えるには `loadSrc()` を呼んでください。

### `autoplay` は `<video>` と同じく opt-in

付けない場合、要素は**ロードして 1 フレーム目で止まります**（ポスターのように）。描画は再生制御とは
独立しているので、キャラクターは画面に出ていて、動いていないだけです。これは HTML の慣習
（`<video autoplay>`）に従ったもので、WebGL Player の要素 `<ss-player>` とも揃っています。

なお、ファミリーのうち*配置する*タイプの Player（Godot / Unity）は逆に既定でオンです。シーンノードには
`play()` を呼ぶコードが無く、属性が**そのコードの代わり**だからです。

## プロパティとメソッド

要素は API を隠しません。自分が作ったものを公開するので、[JavaScript API](./js.md) にあるものはすべて
到達可能です：

| | |
|---|---|
| `element.player` | `SsPlayerWeb` — パーツオーバーライド、イベント、再生制御など全部 |
| `element.surface` | このキャンバスの `SsSurfaceWeb` — `stats()`、`resize()` |
| `element.ctx` | ページ共有の `SsContextWeb` |
| `element.canvas` | 要素が作った `<canvas>` |

```js
const el = document.querySelector('ss-player-webgpu');
await el.loadSrc('/assets/Other.ssab');       // アニメーション名の配列が返る
el.player.setSpeedScale(0.5);
el.player.setPartVisibilityOverride('hat', true, false);
for (const e of el.player.events()) { /* ... */ }
```

### `loadSrc(src, pack?, anim?)`

`.ssab` を取得して再生します。実行時にパックを差し替える手段でもあります。戻り値はアニメーション名の
配列なので、そのまま UI の選択肢にできます。

アニメーション（`anim`、無ければ最初のもの）を選択したあと、初回ロードとまったく同じように `autoplay` を
尊重します。つまり `autoplay` の無い要素は、新しいパックでも 1 フレーム目で止まります。

`pack` を渡すと、要素自身がバイト列を取得してその名前で登録します。`load` は意図的に名前の上書きを
受け取らないためです。

## レイアウトと解像度

* カスタム要素はページが指定しない限り `display: inline` で、インラインボックスは `width` / `height` を
  無視します。そのため要素は、**ページが `inline` のままにしていた場合にだけ `display: block` を
  設定します**。`inline-block`・フレックスアイテム・`none` を選んだ作者の指定はそのまま残ります。
* キャンバスは要素いっぱい（`100%` × `100%`）に広がります。
* バッキングストアは **CSS サイズ × `devicePixelRatio`** なので、HiDPI でも鮮明です。
* どちらも**要素が接続された時点**で計算され、その後のサイズ変更は監視しません。リサイズするパネルに
  置く場合は、要素を作り直すか、`element.surface` 経由で
  [`SsSurfaceWeb.resize()`](./js.md) を自分で呼んでください。
* 要素にはサイズを与えてください。無い場合は 360 × 360 にフォールバックします。

## 誰も見ていないときに止める

`pause-when-hidden` は既定でオンで、アニメーションフレームループを **2 つの**シグナルでゲートします：
キャンバスに対する `IntersectionObserver` と、ドキュメントの `visibilitychange`。モバイルでのバッテリーと、
広告クリエイティブが測定されるビューアビリティ要件のためにあります。

知っておく価値のある挙動が 2 つ：

* **最初のオブザーバコールバックが来るまでは「隠れている」とみなします。** 画面外から始まった要素が、
  すぐ捨てることになる初回フレームを描かないためです。
* API が存在しない場合（またはゲートを切った場合）は、まったく動かないのではなく**常に動きます**。

フレームのデルタは 50 ms でクランプされ、一時停止のあとは時計がリセットされます。バックグラウンドの
タブに戻ったとき、アイドル時間の分だけアニメーションが飛ぶことはありません。

## デバイスロストは自動で処理されます

要素は毎フレーム、デバイスが失われていないか確認し、自分で `restoreSharedDevice` を呼びます。デバイスは
*ページ*のものなので、**最初に気づいた要素がページ上の全要素の分を復帰させます**。再生は中断されたフレームから
再開します。[デバイスロスト](../guide/device-loss.md)を参照。

## エラー

起動・ロード・フレーム処理で投げられたものはすべて捕捉されます。要素は `[ss-player-webgpu]` としてコンソールに
出力し、自分の中身をシンプルなエラーボックスに置き換えます。メッセージはマークアップではなくテキストとして
書き込まれます。属性由来の URL やパック名が混じりうるうえ、エラー経路は HTML をパースし始めるのに適した
場所ではないからです。

最頻の原因は WebGPU 非対応ブラウザです。既定のボックスではなくデザインされたフォールバックが欲しい場合は、
[`sharedContext()`](./js.md) を直接使って `catch` してください。

## ライフサイクル

要素を DOM から外すと、そのプレイヤーとサーフェスが破棄されます。**ページのコンテキストは破棄されません** —
他の要素が共有しているためです。参照を捨てるだけでは済まないのはこの後始末のためで、サーフェスは
スワップチェーンを持っており、存在したことのある要素の数だけリークするからです。

## API を直接使うべき場面

次の場合は [`SsContextWeb`](./js.md) を直接使ってください：

* **1 つのキャンバスに複数キャラクター** — 要素は意図的に 1 対 1 です；
* 自前のフレームループ、または `requestAnimationFrame` 以外で駆動したい；
* デバイスをいつ作るかを制御したい、あるいは WebGPU 非対応時のフォールバックを自分で用意したい；
* すでに自分で管理しているキャンバスがある。

要素がやっていることはすべてその API の上に書かれており、1 ページで両者を混ぜても構いません。
