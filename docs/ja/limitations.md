# 制限事項と適用範囲

この Player が**やらないこと**と、その理由です。ここに書くのは技術的な制約であって、TODO リストでは
ありません。計画中のものや未検証のものは
[ROADMAP](https://github.com/cri-middleware/SSPlayerForWgpu/blob/main/ROADMAP.md) に、各 Face が現時点で
公開している範囲は[スコープと名前の対応](./guide/concepts.md#what-each-face-can-do)の表にあります。

## 適用範囲

* **SpriteStudio 7 の `.ssab` のみ。** SS6 系 Player の `.ssfb` / `.ssfb2` は読めません。`.sspj` から
  再コンバートしてください（[SS6Player for CPP からの移行](./migration/from-ss6-cpp.md)）。
* **コンバートは事前です。** 実行時に `.sspj` を変換するものは無く、コンバータも同梱しません
  （[アセットの準備](./start/assets.md)）。
* **Player は音を鳴らしません。** オーディオイベントは何を何回鳴らすかを伝えるだけで、オーディオ
  スタックに渡すのはアプリケーションの仕事です。

## グラフィックス

### C ABI 経由でデバイスを共有できません { #no-device-sharing-across-the-c-abi }

C Face は渡されたウィンドウハンドル上に**自分でグラフィックスデバイスを構築し、所有します**。あなたの
コマンドリストやレンダーパスへ描き込むことはできません。

これは省略ではなく構造上の帰結です。wgpu の型には安定した C 表現が無く、境界を越えて渡せるものが存在
しません。したがってデバイスを持つエンジンへの組み込みは **Rust 限定**の機能であり、
[アダプタクレート](./wgpu/engines.md)として提供されます。

C から合成したい場合の経路は、オフスクリーン描画＋テクスチャ共有です。

### wgpu は 29 系に固定

Cargo の workspace はちょうど 1 つの `wgpu` に解決し、メジャーが 2 つあるということは互換性のない型が
2 組あるということです。`bevy_render` 0.19 は `wgpu ^29.0.3` を要求し、Slint の `unstable-wgpu-NN` は
メジャーの厳密一致を要求します。つまりこの固定は好みではなく、リポジトリ全体で共有される互換性の契約です。

### MSAA はオフ必須

Player のパイプラインはシングルサンプルです。マルチサンプルのターゲットは、誤って描くのではなく拒否
されます（Bevy アダプタは 1 度警告してスキップします）。

### 色管理をしません

アトラスのバイト列は、渡されたターゲットへそのまま書かれます。WebGL リファレンス Player とまったく同じ
挙動です。sRGB ターゲットでは二重にエンコードされて全体が明るくなりすぎるので、非 sRGB ターゲットを
渡すか、sRGB 空間で合成してください。HDR（`Rgba16Float`、リニア光）ターゲットに対しては、この出力は
トーンマッピング的に正しくありません。

### OpenGL / WebGL バックエンドはありません

レンダラーは頂点ステージにバインドしたストレージバッファから頂点を引きます。OpenGL では 4.3 / GLES 3.1
以降でしか公開されておらず、WebGL には存在しません。GL アダプタはどこでも選択も検証もされていません。
インスタンスは wgpu の primary バックエンド（Vulkan / Metal / DX12 / WebGPU）を取り、C API のバックエンド
選択肢は DX12 / Metal / Vulkan です。

**WebGPU が無い環境の答えは
[`ssplayer-webgl`](https://github.com/cri-middleware/SSPlayerForWeb)** です。こちらはメンテナンスされて
おり、この Player の描画パリティの基準でもあります。WebGPU 非対応ブラウザからは `catch` 一つでそちらへ
フォールバックできます（[Web ではじめる](./start/web.md#requirements)）。

### マスク：24 ライタ

カバレッジビットマップバックエンドはマスクライタ 1 つにつき 1 ビット、24 ライタを扱います。これはマスク
仕様自身の数値で、リファレンス実装と共通です。ここで手を抜いた結果ではありません
（[マスク](./guide/masks.md)）。

## 再生

### 1 キャラクターにつき 1 フレーム 1 回の `update`

`SSScene::update` はタイムラインの前進とジオメトリ構築を一体で行うため、同じキャラクターを 1 フレーム内で
2 つのシーンに渡すとアニメーションが**2 回進みます**。したがって 1 つのキャストを 2 つのビュー（メイン
ビューと、同じキャラクターのミニマップ）に描くことはできません。Bevy アダプタは 2 つ目以降のビューを
警告付きでスキップします。

1 デバイスに複数のシーンがあること自体は問題ありません。できないのは、1 **キャラクター**が 2 つのシーンに
またがることです。

### インスタンスの子はレイヤー化されません

別パックのアニメーションを再生するパーツは自分の再生コンテキストで動き、ルートのフレームのスロットから
駆動されます。[トラックスタック](./guide/motion-blending.md)は、あなたが持っている Player のキャラクターに
対して働き、そのインスタンスの子には及びません。

### クロスフェードはインスタンスツリーを再構築しません

それが「切り替え」ではなく「フェード」である理由です。**インスタンスパーツの構成が異なる**アニメーションへの
クロスフェードは対象外で、その場合は `set_animation` を使ってカットを受け入れます。

### 再生区間のラベル指定はありません

区間はフレーム番号で指定します（`set_animation_section(start, end)`）。SS6 Player の `labelRangeStart` /
`labelRangeEnd` のようなラベル文字列に相当するものはありません。

### パーツ単位の反転オーバーライドはありません

反転はオーサリングされたキーフレームに従います。`set_part_flip_override` に相当するものはありません。

### エフェクトのシード指定はありません

エフェクトの乱数シードは再生スロットごとに決まります。SS6 の `SeedOffsetSet()` に相当するものはありません。

## 配布

* **リリースに含まれるのは静的ライブラリのみ**です（C Face 向けの `libssplayer_wgpu.a` /
  `ssplayer_wgpu.lib`）。共有ライブラリも同梱すると、同じことをする 2 つ目の方法のために、コード署名・
  SONAME・インポートライブラリの対応付けを毎回のリリースに背負うことになります。ローカル作業用には
  `build.sh` が共有ライブラリも生成します。
* **まだ何も公開されていません。** crates.io / npm / リリース zip はそれぞれ、各
  [はじめる](./start/rust.md)ページに書かれた条件を待っています。SDK リポジトリが private の間は、
  どの経路もアクセス権を持つ人によるソースビルドです。
